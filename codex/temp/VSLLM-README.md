# VSLLM 福利自动化

## 运行方式

### 常驻运行（推荐）

```powershell
.\vsllm
```

现在正常运行时只保留 **Node.js 命令行进程**，签到、广告、答题和翻牌都直接通过站点接口执行，不再长期挂着 Chrome。

- 存在有效认证：读取 `.vsllm-auth.json`，不启动 Chrome。
- 首次运行或认证过期：临时打开 Chrome，登录成功并保存认证后立即关闭 Chrome，然后继续由 Node 后台运行。
- 脚本不读取或保存密码。

旧版本升级后的第一次启动因为还没有 `.vsllm-auth.json`，会短暂打开一次 Chrome 来迁移认证；之后认证有效期间不会再打开。

### 只更新登录认证

```powershell
.\vsllm login
```

此命令只打开 Chrome 完成登录、更新 `.vsllm-auth.json`，保存后自动关闭，不执行签到、广告、答题或翻牌。

站点当前实际使用的是登录 Cookie、`new-api-user` 和设备认证请求头，而不是一个已确认可长期使用的单独 Token。因此脚本没有猜测 Token 格式，而是从登录后的浏览器请求中安全提取这些认证数据。

### 严格后台模式

```powershell
.\vsllm headless
```

此模式永远不会由常驻服务主动打开 Chrome：

- 认证有效时直接在 Node 后台运行。
- 认证缺失或过期时，Node 窗口保持运行并等待，不会退出。
- 此时在另一个 PowerShell 窗口执行 `.\vsllm login`；认证保存后，原 Node 服务会自动检测并恢复。

### 只执行一轮

```powershell
.\vsllm once
```

严格后台且只执行一轮：

```powershell
.\vsllm headless once
```

如果严格后台单轮模式缺少有效认证，脚本会退出并提示先运行 `.\vsllm login`，不会无限等待。

## 自动任务

- 每日签到。
- 广告奖励：读取每日次数、冷却时间和观看时长，完整等待后领取奖励，不跳过广告计时。
- 每日答题：只提交去除首尾空格后文本精确等于 `9.11` 的选项；没有该选项或接口失败时不猜测其他答案。
- 翻牌抽卡：读取剩余次数、充能和服务端下一次可用时间。
- 翻牌成功后单独输出本次获得额度。

每轮执行后，会从翻牌 `next_available_at`、广告任务 `next_available_at` 和次日零点后 5 秒中选择最早时间继续运行。

## 认证与安全

- 浏览器资料保存在 `.vsllm-profile`。
- Node 接口认证保存在 `.vsllm-auth.json`。
- 两者都包含敏感登录信息，请勿分享或提交到版本库。
- 接口响应如果更新 Cookie，脚本会同步更新 `.vsllm-auth.json`。
- 收到 HTTP 401 时视为认证过期：普通模式临时打开登录窗口；严格后台模式等待另一个窗口执行 `.\vsllm login`。
- 如果网站要求 Turnstile/CAPTCHA，请自行在浏览器中处理；脚本不会绕过验证码。

## 每日答题说明

- 找到 `9.11`：提交对应的 `answer_index`。
- 没有 `9.11`：不提交其他选项，日志提示手动处理。
- 开始或提交接口失败：不重试其他答案。
- 如果 `9.11` 被判定错误：当天不再尝试其他答案。

## 让修改生效

旧的 VSLLM Node/Chrome 进程不会自动加载新代码。请先关闭旧程序及其 Chrome 窗口，再重新执行 `.\vsllm`。首次重启会生成新的 `.vsllm-auth.json`。
